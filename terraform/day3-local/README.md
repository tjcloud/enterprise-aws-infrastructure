# Day 3: Terraform Local File Automation

## Overview

This lab introduces Terraform and Infrastructure as Code (IaC) by using the Terraform Local provider to create a project report on my local computer.

The goal was to learn how Terraform configuration files work together to define resources, manage variables, and display outputs.

**This lab runs locally on macOS. It does not deploy or monitor AWS resources and incurs no AWS charges.**

## Technologies Used

- Terraform
- HashiCorp Local provider
- HCL (HashiCorp Configuration Language)
- macOS Terminal
- Git and GitHub

## Project Structure

```text
terraform/day3-local/
├── versions.tf
├── variables.tf
├── main.tf
├── outputs.tf
└── .terraform.lock.hcl
```

## What I Built

I created a Terraform configuration that generates a local file named `project_report.txt`.

The report contains:
- Project name
- Environment
- Project owner
- Execution status

## File Descriptions

- `versions.tf`: Defines the Terraform version requirement and Local provider.
- `variables.tf`: Defines configurable inputs, including project name, environment, and owner.
- `main.tf`: Defines the local file resource and its report content.
- `outputs.tf`: Displays the report path, environment, and project summary.
- `.terraform.lock.hcl`: Records the selected provider version for consistent initialization.

## Skills Practiced

- Writing Terraform configuration using HCL.
- Defining and referencing input variables.
- Creating a local resource with the Local provider.
- Defining Terraform outputs.
- Formatting and validating Terraform code.
- Reviewing execution plans before applying changes.
- Applying configuration and verifying generated output.
- Using Git and GitHub to manage project files.
- Excluding local state, generated files, and variable files from version control.

## Commands Used

```bash
terraform fmt
terraform init
terraform validate
terraform plan
terraform apply
cat project_report.txt
terraform output
```

## Security and Cost Notes

This exercise uses a local file resource rather than AWS infrastructure. The local `terraform.tfvars`, Terraform state files, and generated report should not be committed to GitHub.

## Learning Outcome

This lab provided hands-on practice with Terraform's basic workflow: defining configuration, supplying variables, validating code, reviewing a plan, applying changes, and checking outputs.
